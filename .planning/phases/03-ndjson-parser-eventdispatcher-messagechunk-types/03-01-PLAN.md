For each of the 12 existing `.expected.json` files, rewrite the `chunks` array to reflect the EXACT output that the EventDispatcher will produce per the mapping table in CONTEXT.md. The mapping rules are:

**Event-to-chunk mapping (apply to every line in the .ndjson):**

| NDJSON event | Output chunk |
|---|---|
| `{"type":"init", "session_id":"X", "model":"Y", ...}` | `{"type":"system", "subtype":"init", "sessionId":"X", "model":"Y"}` |
| `{"type":"message", "role":"user", "content":"C", ...}` | `{"type":"system", "subtype":"message", "role":"user", "content":"C"}` |
| `{"type":"message", "role":"system", "content":"C", ...}` | `{"type":"system", "subtype":"message", "role":"system", "content":"C"}` |
| `{"type":"message", "role":"assistant", "content":"C", ...}` | `{"type":"assistant", "content":"C"}` |
| `{"type":"tool_use", "tool_name":"N", "tool_id":"ID", "parameters":{...}, ...}` | BUFFERED — not yielded until matching tool_result. Then yield: `{"type":"tool", "toolName":"N", "toolId":"ID", "parameters":{...}}` |
| `{"type":"tool_result", "tool_id":"ID", "status":"S", "output":"O", ...}` | Triggers pair release: first the buffered tool chunk, then `{"type":"tool_result", "toolId":"ID", "status":"S", "output":"O"}`. If the tool_result has an `error` field, include `"error":{...}`. |
| `{"type":"error", "error":{"code":429, "status":"RESOURCE_EXHAUSTED", ...}}` | `{"type":"rate_limit", "code":429, "message":"...", "status":"RESOURCE_EXHAUSTED"}` |
| `{"type":"error", "error":{...}}` (non-rate-limit) | Not a chunk — the dispatcher throws. Mark in expected.json as `{"_throws":true, "errorType":"GeminiError", "errorMessage":"..."}` |
| `{"type":"result", "status":"success", ...}` | `{"type":"result", "sessionId":"<from init>", "stopReason":"end_turn"}`. NOTE: `stopReason` maps from `status`: "success" -> "end_turn". The `sessionId` is carried forward from the init event. |
